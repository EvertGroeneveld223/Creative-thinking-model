Rewritten 2026-11-09 after an audit and a patch in Claude Code. This file types no result numbers of its own. **Every result is in `CLAIMS.md`, generated by `python claims.py`**, and is cited here by id.

## 1. Goal (user's words, condensed)
Develop the framework **Object1 x Object2 + Bridge -> Novel Solution** into an AI creativity engine that must:
1. produce patterns **not found on the web** (novelty),
2. **explain** them with a **sourced rulebook** (explanation = understanding; "it just works" is not an explanation),
3. check every idea with a **return-to-sender** loop.
The user wants the idea space in **3D** (X, Y, Z) with **noise as waves** that disturb data cells while they travel. Rules are assumed always right (no human-error handling for now). The AI asks Who / What / Where / Why / How.
The user dropped the "memory box" idea and kept return to sender.

## 2. Core model (math)
- **Rule** r = (L -> R, WHAT, WHERE, WHY, WHO). HOW is produced per use (which rule, which part, which substitution).
- **Explained(a = b)** iff both sides reach the same normal form using rules only. Stuck parts are **gaps**; each gap is the next web search.
- **Return to sender** gives reply (w, e, n): works (computed by the world), explained (rulebook), novel (web). Cube corners: NEW (1,1,1), KNOWN (1,1,0), DISCOVERY (1,0,1), GAP (1,0,0), CONTRADICTION (0,1,*), FALSE (0,0,*).
- **Idea space**: X = breadth/rules, Y = areas (Y>=2 is a bridge), Z = depth.
- **Wave noise**: eta(r,t) = sum_i A_i sin(k_i.r - w_i t + phi_i) (3 waves), d = |eta|/sum A. Outbound transit mutates with prob d. The reply goes through `s4_merging/channel.py`, is checked by SHA-256 and resent if corrupted, so return noise costs time and cannot change the answer.
- **Polarized waves**: four channels RULE, AREA, DEPTH, MOD, one wave each; amplitude x1.25 if useful, x0.8 if bad, clamp [0.3, 2].
- **Control**: the shuffled modes redraw every phase at every step, keeping the noise level and removing the wave.
- **worth** = log2(naive bound / observed period) / size. Shortest-form canonical check before any novelty search. A looser bound is a DISCOVERY signal, not a pass.
- **Test domain**: integer sequences mod m built from blocks fib, luc, tri, sq, ds (digit sum). Merge rules: M_SQ, M_TRI, M_DS (only if the modulus divides 9), M_MOD. Exact period via Newton forward differences per residue class.
- **Symmetry ladder**: R_COMP, R_MULT (g(n+h) = a*g(n) mod P and f(a*k) = f(k) mod m => period divides h), R_QUOT, affine maps, R_CRT, R_PARITY, R_ZERO, R_CLASS, R_BLOCK (the outer layers count as one function G: f_k(n+h) = tau(f_k(n)) with tau affine and G(tau(x)) = G(x) on the image => period divides h; d = 2 lets tau differ for even and odd n).
- **Rule store** (`s9_loop`): gap -> LADDER candidate fitted on the first values -> hold-out value -> `rules.json` -> read back by `predict`; a later disagreement marks it REFUTED. Passing tests sets w, never e. Only a linked written proof sets e.

## 4. Where things stand (numbers in CLAIMS.md)
- **Rulebook loop**: works on Peano addition, including a rule really read from a page [C01]. Reading rules from pages in general is not solved.
- **Exact periods**: the merging engine agrees with brute force wherever both apply, and digit sums mostly get no proof [C02].
- **Why-chains from identities**: complete for Fibonacci and Lucas [C03, C04], partial for Pell [C05], none for tribonacci.
- **Table rules**: the ladder with R_BLOCK reaches every tested chain [C06], and held up on fresh moduli and a scrambled null [C07]. These search computed tables. They are finite proofs for one m, not derivations from identities.
- **Do waves help?** Mutation helps. No benefit from the wave structure was detected at the same noise rate [C09]; the older comparison could not tell [C08]. Return noise does not change results [C10].
- **Novelty**: the hunt now asks several kinds of source and checks OEIS matches on every listed term [C11, C12]. Most classes are REVIEW, waiting for a person. The F(F(n)) table is known [C13].
- **Theorems**: Theorem 1 (exact, powers of 5) and Theorem 2 (upper bound, odd prime powers) have written proofs [C14], not reviewed by a mathematician. Lemma V is sourced [C19]. The general formula is a tested conjecture, including a blind test [C15]. The odd-modulus pattern is tested, not proved [C16]. Not found in the searches listed, which is not the same as new [C18].
- **Learning**: the rule store closes the loop on a small scale [C17]. It finds little, only at small primes, using a template written with Theorem 1 in mind.
- **Calibration**: see the ledger [C20]. Its predictions were scored on checks their author designed, so read it as a weak signal.

## 5. Open problems (priority order)
1. **Prove or refute Conjecture 2** (PROOFS.md): the lower bound and "no saving otherwise". The odd-modulus pattern is its f = F part. Start from the kernel of L mod q: L(x) = L(y) with y - x even factors by the I3 identity, and pairs of opposite parity are the hard case.
2. **Have a person review** PROOFS.md and the REVIEW list in `hunt_results.json`, and read what could not be fetched (`not_read` in `opened_pages.json`). Code cannot do these.
3. **Decide what to do with waves.** No benefit was detected in this one self-built world. Whether to keep them as the framework's noise is the user's call. A different domain could differ, but there is no evidence of that yet.
4. **Make the miner generalise across primes**, so a rule like Theorem 2 could come from the engine rather than from Claude. It needs a richer template, and a test that does not know the answer.
5. **Finish the why-chains**: inner Pell-Lucas (always even, so a quotient step is probably needed), then tribonacci, which has no identities here.
6. **A general-web source code can use.** DuckDuckGo blocks code; agent web searches are recorded by hand in `opened_pages.json`.
7. **Better candidate filters.** The title and abstract word filter still lets through much noise.
8. **Fuzzier domain and an external world** (simple mechanics, scheduling). Untested. Everything so far is in a world the assistant built.

## 6. Honest limits
- Evidence only counts if it comes from code or opened pages.
- All computed results are in one self-built domain, and most tests were designed by the same assistant that wrote the rules.
- No proof assistant was available, so `prove.py` checks steps, not the reasoning between them.
- An earlier version of this file said confidence ran 0.2 to 0.4 above accuracy in past runs. No data for that is in this repo, so it was removed; the ledger now measures this going forward.
